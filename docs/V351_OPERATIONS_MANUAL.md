# v3.5.1 无数据库版运维手册

## 部署

1. 核对发布归档中的 ZIP SHA-256 与 `release_manifest.json`。
2. 将 `ImageUploadTool_v3.5.1_no_database_release.zip` 解压到新的安装目录，不覆盖旧版本、现场配置或源目录。
3. 首次启动前，安装目录不得包含 `config.json`、`logs/`、`data/` 或 `resume_data/`。
4. 复制 `config.template.json` 为 `config.json` 后按现场权限配置，或首次启动时由程序生成默认配置。

## 运行红线

- 源、目标和备份目录必须互不相同且不相互嵌套。
- 生产放行前使用 SMB/FTP 真实端点完成连通性和测试文件核对。
- 出现误报成功、重复上传、错移/误删、状态损坏、磁盘检查失败或连续三次不可恢复失败时立即停止运行，保留日志和状态文件。
- 不删除源文件作为故障处理手段；上传和归档账目必须可逐文件解释。

## 自动磁盘清理

- 自动清理已经与智能去重门禁拆分，只允许管理员配置；智能去重仍保持关闭。
- 自动清理只能使用“移入回收站”模式，回收站能力不可用时禁止启用或继续删除，不会自动降级为永久删除。
- 所有监测目录必须存在并位于同一磁盘；目标占用率必须低于触发占用率。运行时按文件修改时间全局最旧优先处理，并写入独立清理审计日志。
- Windows 本地回收站通常仍占用原磁盘空间；若移动后可用空间没有增加，程序会记录“回收站未释放空间”并安全停止。当前版本不会自动清空回收站或自动永久删除。
- 配置保存后定时检查立即生效，上传任务运行时暂停定时清理，上传结束后恢复。现场放行前必须完成磁盘压力、回收站失败、路径失效和退出取消验证。

## 停止、重启与回退

1. 正常停止并等待 Worker 退出，保留 `logs/`、`data/`、`resume_data/` 和 `config.json` 的时间戳副本。
2. 回退版本解压到独立目录，禁止覆盖 v3.5.1 安装目录。
3. 经管理员确认配置字段兼容后复制配置副本，先停止状态启动并检查路径。
4. 仅使用非生产测试文件核对目标和备份；失败时停止回退程序并恢复原目录，不操作源文件。

## 现场验收

现场必须完成真实 SMB/FTP、断网恢复、服务端重启、同名代际、强杀/断电、磁盘压力和 24--72 小时长稳测试，并填写 `V351_FIELD_ACCEPTANCE.md`。现场证据应与验收表一并归档，由发布负责人复核后决定是否放行。在现场负责人签署前，发布结论保持 `NO-GO`。
