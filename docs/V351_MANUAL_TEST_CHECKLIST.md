# v3.5.2 现场验证手工测试清单

本清单只记录开发机不能替代的实际测试。当前状态统一为 **待测试 / NO-GO**；执行人不得预先勾选，不得用回环 FTP、模拟共享或开发机结果替代。

## 0. 测试前冻结

- [ ] 重新计算候选 ZIP SHA-256，与同目录 `.zip.sha256` 一致。
- [ ] 解压到全新目录，不覆盖旧版；目录内首次启动前没有 `config.json`、`logs/`、`data/`、`resume_data/`。
- [ ] 记录 Windows 版本、机器名、测试人、日期、SMB/FTP 真实端点和现场最大文件。
- [ ] 从 `docs/field_evidence.template.json` 复制出 `field_evidence.json`，所有附件放在其同目录的 `evidence/` 下。

## 1. 登录、改密与权限

- [ ] 首次启动后，管理员使用默认口令 `Tops123` 可直接登录，只提示风险，不强制改密。
- [ ] 登录后“源文件夹”“目标文件夹”“浏览”“开始上传”均可用；磁盘清理菜单仅管理员可用。
- [ ] 普通用户默认口令可登录，业务控件按普通用户权限启用，磁盘清理不可用。
- [ ] 管理员将一个账号改为符合规则的新密码，退出后旧密码失败、新密码成功。
- [ ] 改密后再保存一次普通配置，完全退出进程并重启，新密码仍有效。
- [ ] 保留登录页面、改密成功、重启后登录和权限状态截图；严禁在截图或日志中记录明文密码。

## 2. 自动磁盘清理

- [ ] 管理员打开磁盘清理，启用自动清理，选择与上传源/目标/备份均不嵌套的测试目录。
- [ ] 配置保存后完全退出并重启，开关、目录、阈值、格式过滤仍正确。
- [ ] 制造达到触发阈值的磁盘压力，确认只选择匹配格式、按修改时间最旧优先，并在每个文件操作前复核身份。
- [ ] 替换一个已扫描的同路径文件，确认新文件保留，日志出现“候选已刷新/文件已变化”。
- [ ] 注入回收站不可用或移动失败，确认文件保留，且绝不降级为永久删除。
- [ ] 运行中撤销启用、改变为不安全配置、断开清理路径或退出程序，确认任务安全停止。
- [ ] 核对 `logs/cleanup_YYYY-MM-DD.log` 的 START、DELETE_OK/DELETE_FAIL、END 记录和计数。

> 重要限制：当前自动清理只允许移入回收站。Windows 本地回收站通常仍占用原磁盘空间，因此程序发现可用空间未增加时会安全停止并记录“回收站未释放空间”。如现场目标是自动释放磁盘容量，必须由管理员另行清空回收站；当前版本不会自动清空回收站，也不会自动永久删除。

## 3. 真实 SMB / FTP / 故障恢复

- [ ] 真实 SMB 上传现场最大文件；目标哈希正确，源仅在归档记录落盘且归档成功后移动。
- [ ] 真实 FTP/FTPS 上传现场最大文件；最终名只在临时对象完成、远端大小确认和 rename 成功后出现。
- [ ] 双协议模式让单侧失败，再恢复；不误报成功，源保留，已成功通道不重复提交。
- [ ] 传输中断网、恢复网络并重启服务端；人工暂停不得被网络恢复覆盖。
- [ ] 同一相对路径快速生成两个不同内容代际；旧任务不得移动或删除新代际。
- [ ] 传输与归档阶段分别强杀进程并重启机器；待重试/待归档状态可解释，源和已提交目标不丢失。

## 4. 24–72 小时长稳与对账

从有 Python 3.13 和 `psutil==7.0.0` 的验证工作站运行（被测机器本身仍可保持无 Python）：

```powershell
python field_tools\release_soak_test.py `
  --exe "C:\Release\ImageUploadTool_v3.5.2\ImageUploadTool_v3.5.2.exe" `
  --duration-seconds 86400 `
  --sample-interval 30 `
  --output ".\evidence\soak.json"
```

- [ ] 至少运行 24 小时；资源报告 `passed=true`，无残留进程、句柄/线程/内存持续增长。
- [ ] 同期执行真实上传、断网恢复、服务端重启和强杀场景，并保存应用日志。
- [ ] 对账满足：发现数 = 待重试数 + 归档数 + 失败数；重复数 = 0；未解释差额 = 0；误报成功、错移、误删均为 0。
